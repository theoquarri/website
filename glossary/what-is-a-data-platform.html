What is a data platform?

Theo Leslie · 2 min read

← Glossary

A data platform is software that collects data from a business's systems and documents, cleans it, joins it, and serves one consistent version to reports, people and AI tools. IBM defines it as "a technology solution that enables the collection, storage, cleaning, transformation, analysis and governance of data". Wikipedia puts it more plainly, as "a data delivery point for application and reporting software". It sits beside the systems that run the business, such as the ERP, the scale system and the optimiser. It doesn't replace them.

The parts

IBM describes "five foundational layers": storage and processing, ingestion, transformation, business intelligence and analytics, and observability. Ingestion brings data in from each source. Transformation cleans it and joins it. Storage keeps its history. Analytics serves it. Observability watches for breaks.

In a timber business

Getting data in comes first, and from older systems with no way to export it, that can be the hardest part. Once it is in, the layer that most often decides the result is transformation, and within it, the joins. The same wood is a stem in a harvester file, a load on a scale ticket, logs in the yard, boards in a tally and lines on an invoice. Each system names and measures it differently. A data platform is useful when it joins those records correctly, so that a question like what did this contract's wood earn? has one answer.

Joins also cross documents. From Quarri's own work with a forestry operation: one release cycle matched 1,400+ bills of lading across 70+ invoices, with every rated row and every eligible weigh record accounted for. A wrong join can drop records or count them twice, and neither shows up as an error message.

What it isn't

A data platform isn't an ERP, which runs transactions, or a dashboard tool, which only displays data. It isn't a data warehouse either, though it usually contains one. And it isn't a single system that replaces the others. It works alongside them.

What to check

Ask how each join between your systems is defined, who can see the rule, and how the platform shows records that failed to join. Ask whether it keeps history, so past reports can be rebuilt. And ask whether it reads documents, such as tickets and invoices, as well as systems.
